# 界面用语

面向使用者的标题、按钮、状态和提示使用大白话。接口、字段、错误码和技术详情保留准确名称，不为改文案改变交易逻辑。

这是一条全产品要求：十个模块的主页面、展开内容、表单报错、悬停提示、手机布局及通知都要遵守。先写用户关心的情况和动作，再提供需要排查的技术信息；不能只把英文术语换成难懂的中文术语。

- 状态直接说“正常”“需留意”“交易受限”“距更新多久”“正在等什么”，不用内部枚举充当解释。
- 同一概念保持同一说法，但保留必要区别：公开买卖报价不是保证成交，本次询价不是已经下单，多空相抵后的差额不是所有未配对持仓的合计。
- 交易所品牌、币种、合约地址、API Key 等需要辨认的名称保留；技术文档的接口、字段、命令和单位不改。普通说明先用中文，必要时在括号中给出原名。

| REST 基线 / WS 预热中 | 定期查询的数据 / 等待首批实时数据 |
| 双腿 | 按语境使用两边交易、两笔订单或两边持仓 |
| 快照 / 冷启动 / 流静默 | 本次或上次数据 / 首次读取 / 实时推送未更新 |
| 熔断 / 限频 | 异常后暂停请求 / 请求受限 |
| 持久化 / volatile | 已保存 / 临时生效，重启后丢失 |
| 已入队 / 待投递 | 排队发送中 / 待发送，不等于已经送达 |
| 跨 Quote / 映射未通过 | 计价币不同，仅供对比 / 尚未确认是同一资产 |
| 毛边际 / 费后净边际 | 扣费前预估收益 / 预计净收益，不是已到账收益 |
| 构建新双腿 | 创建交易计划，不是立即下单 |
| 双腿提交 / 最低双腿深度 | 提交两边订单 / 每边盘口最低金额 |
| 裸露金额 / 成交锚点 | 未对冲金额 / 关联成交记录 |
| 动作账本 / Webhook 设置 | 操作记录 / 消息通知；通知方式保留 Webhook、Bark 名称 |
| 应用确认 / 仅传输成功 | 推送服务已确认接收 / 网络请求成功，接收待确认；均不表示手机已展示 |
| 净 Delta / 裸单暴露 | 多空净差额 / 未配对持仓金额；前者是多空相抵后的差额，后者是未配对持仓，不能混成一个数字 |
| 当日已实现 PnL / 未实现 PnL | 今日已结算盈亏 / 持仓浮动盈亏；估算和待确认标记仍保留 |
| 多腿 / 空腿 | 买入一边 / 卖出一边；交易所、做多/做空和现货/合约属性仍显示 |
| Kill Switch / VaR-99 | 交易急停 / 单日损失估计；说明急停仍允许减仓或平仓，风险估计不是最大损失保证 |
| 补库 / 备款 | 补充余额 / 预留资金；不称为加仓，不代表已经转账 |
| CrossEx 路由 / 毛价差 | 交易通道 / 扣费前价差；不能说成扣费后盈利 |
| 退避基数 / 队列上限 | 重试基础等待 / 最多待发消息；原有单位和设置范围不变 |
| 首腿 / 次腿 | 第一笔订单 / 第二笔订单；不把提交顺序误写成固定先买后卖 |
| 补偿 / 收口 | 交易补救 / 处理未对冲持仓；不是赔付，提交补救订单也不等于处理完成 |
| 单腿强平保护 | 防强平退出；任一边接近交易所强平价时，尝试平掉两边持仓，不承诺一定能避免强平 |
| 确定性机会 | 符合条件的机会；符合当前筛选条件，不代表保证盈利 |
| VWAP 滑点 / 滑点阶梯 | 预计成交价偏差成本 / 不同价格下的可成交金额；金额、价格范围与计算方式不变 |
| 新双腿 / 筛选独立机会 | 找机会 / 查找新机会；说明这是新交易，不会为当前持仓补单 |
| 双腿偏差 / 连续确认样本 | 两边金额允许偏差 / 连续确认次数；输入报错也使用相同名称 |
| 匹配名义价值 | 已配对交易金额；明确不是保证金，避免误解止损比例 |
| HedgeTicket 提交权威 | 下单前必须通过两边的交易检查；保存密钥或显示可用不等于可以直接下单 |
| Spot Ticks / WS RTT | 现货行情 / 连接状态与耗时；订单处理耗时、请求耗时和数据更新间隔分别说明 |
| 最大并发 / 入场冷却 | 最多同时交易数 / 再次开仓间隔；输入报错也使用同样的名称 |
| 票据阻断 / 执行规格 | 交易条件未满足 / 交易规则；说明尚缺什么，不只给出内部状态 |
| 发行映射 / 合约映射 | 发行方资料 / 代币合约；找到官方合约不等于发行方已核对 |
| Fee schedule fixture | 内置参考费率；明确不是用户账户的实际费率 |
| 名义金额 / 单笔名义上限 | 交易金额 / 单笔交易金额上限；不是保证金，计算仍按原规则 |
| 阻断 / 降级 | 按场景写“检查未通过”“暂不能交易”“部分异常”，不能把受限说成正常 |
| 补偿单 / 已重放 | 补救订单 / 已返回原请求结果，未重复下单；不是赔付，也不是新成交 |
| Secret 存储 / 可持久化 / 仅本进程 | 密钥保存方式 / 重启后保留 / 重启后丢失；是否加密单独说明 |
| 暂停采样 / 账户权益覆盖未完整 | 暂不能记录账户净值 / 还没有读到所有账户的完整资产数据；已有余额与持仓仍可查看 |
| 投递运行数据依据 / 提醒冷却 | 通知发送情况 / 重复提醒间隔；不把排队或发送请求等同于手机收到 |
| 账本事件 / 原执行未收口 | 交易过程 / 上次交易尚未处理完；保留订单编号、时间及实际状态 |

这套规则用于全部十个模块及共用导航、通知、确认框、表格和窄屏标签，不只用于 README。交易所品牌、币种、金额单位、API Key 等需要用户辨认的名称保留。原始错误、协议名和编号可在技术详情中查看，不能删掉诊断信息来假装问题解决。

文案要说清动作和结果，例如“发送测试通知”“检查交易计划”“只平掉这笔仓位，不会反向开仓”。不要把同一个词机械替换到所有地方：买一价是别人愿意买的最高价，不是用户买入的价格；“两边价格未更新”也不能简写成“没机会”。

- 提示先说发生了什么、影响什么，再说可以做什么；请求编号、原始错误和协议字段放在技术详情。
- “已受理”不能改成“已成交”，“正在核对”不能改成“失败”，“已完成”不能改成“已盈利”。
- 缺失数据明确说明，不用零值或绿色状态补齐；旧数据可查看，但不能当作当前可执行条件。
- 不改内部字段、路由、状态枚举、幂等编号或 API 协议。自动化和手动操作使用同一套说法。
- 后台原始错误不能靠改文案掩盖；旧接口返回的文字仍要能识别，分类规则不能因为显示名称改变而失效。
- 文案改变后检查桌面与窄屏的换行、按钮和关键数字，避免长文字遮挡动作。
- 撤单后分别说明“确认未成交”“已成交一部分”“成交数量待核对”。撤单不是平仓，两边金额相抵也不代表没有持仓；数量未知不显示为零。
- 补救订单分别说明“成交数量待核对”“仍有持仓未处理完”“持仓已处理完”。只有原订单和补救订单都结束、成交数量核对后没有剩余持仓，才能显示处理完成；处理完成不代表盈利。
- 平仓记录、补救详情和自动化退出记录使用同一套金额提示：未核清的零值显示“待核对”，已有估算保留“估算”标记。本次平仓完成只说明这次目标数量已成交，不代表整个账户没有持仓，也不代表已经盈利。
- 模拟和实盘分别说明：模拟记录写“模拟成交记录，非真实交易所成交”；实盘只有受理回复时写“仅确认受理，成交待确认”。汇总、策略表现和逐笔明细保持一致，环境未知时不当作模拟成交。
- 复盘中的日期写明是“开仓”还是“平仓”。已确认全部平仓的交易按平仓时间列出，原始开仓时间继续保留；更新记录或补齐费用不会把同一笔已确认平仓移到另一天。
- 历史读取失败时写“历史读取失败”，已有结果写“上次数据”，不写“暂无交易”或“收益为零”。首次失败不展示盈亏汇总；持仓页依赖的已结算盈亏也应显示未知，不能靠部分缓存拼出完整收益。
- 底部通知先展示可读原因，错误编号、请求编号及来源放在“技术详情”。长文字可以换行或滚动，不能直接裁掉；正在阅读或展开详情时暂停自动关闭，关闭按钮始终可用。关闭通知不表示问题已经解决，页面仍保留失败状态。临时通知保持去重及数量上限，不冒充完整消息历史。

## 本轮验证（2026-09-26）

- 已调整十个模块的常用标题、按钮、表头及提示，清理重复文案；不改接口字段、金额计算、交易规则或原始错误。
- 顶部接口异常先用中文说明是哪类功能出了问题，展开后仍可查看交易所、原始错误和请求信息。
- 浏览器已检查十个模块的桌面及窄屏导航，并检查交易确认、通知计划检查、复盘盈亏、CrossEx 表格和状态详情。复盘中的估算与已确认金额继续分开显示。
- 使用隔离接口完成前端交互验证，不代表已验证真实交易所的全部错误消息；此次未进行实盘或对外发送通知。

## 状态提示补齐

- 补齐行情来源、首次读取、数据过期、持仓风险、订单受理、提醒保存与排队发送等状态用语。技术详情仍保留原始错误码、请求编号和后台返回内容。
- 期货、机会扫描与自动化统一使用收益预估和交易计划用语；计价币不同、资产不同、缺少汇率时明确说明只能观察，不把原始价差说成可获利金额。
- 十模块桌面/窄屏导航、期货五策略窄屏标签与动作、旧数据保护、订单受理与成交区分、提醒临时保存与持久保存均经过相关浏览器检查。详细结果及未验证边界见 PRODUCT_ACCEPTANCE.md；并非穷举所有真实交易所的原始错误。
- 操作按钮、平仓失败、自动化流程、链上提交与股票提醒继续使用同一套说法。未知仍是未知，排队不等于送达，已丢弃的消息不显示为等待重试；只改显示，不改协议状态或后台重试规则。

## 展开内容同样使用大白话

- 普通详情、辅助说明、输入校验和窄屏标签也遵循本规则，不只是页面标题。原始接口返回内容、错误码和技术字段保留用于排查，不机械翻译交易所品牌或接口标识。
- 链上机会用“预计有收益”“可创建计划”“尚不能交易”，不把报价测算写成“已盈利”。缺少换算汇率或尚未确认是同一资产时，明确说明只能比较原始价格。
- 更新文字时一起更新相关标签断言；只跑涉及页面的浏览器检查，确认真实渲染、输入和状态切换没有受影响，不为文案修改重跑全仓测试。
- 历史记录的显示名称也遵循本规则，但不改保存的流水、编号或金额；必要时在提示中保留原始名称，便于核对。2026-09-27 已补齐交易金额、补救、未通过和部分异常等用语，验证结果见 PRODUCT_ACCEPTANCE.md。
