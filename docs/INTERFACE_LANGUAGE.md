# 界面用语

面向使用者的标题、按钮、状态和提示使用大白话。接口、字段、错误码和技术详情保留准确名称，不为改文案改变交易逻辑。

| 原术语 | 界面表达 |
|---|---|
| 工件 / 确定性执行工件 | 执行信息 / 执行计划 |
| 预检 / 门禁 | 交易检查 / 执行条件 |
| ACK / 终态 | 受理 / 最终结果 |
| 闭环 | 完整流程 |
| 运行态 | 运行状态 |
| 净敞口 | 未对冲金额 |
| 回执 | 处理结果；按场景使用平仓结果、成交结果或交易记录 |
| 核验 / 证据 | 核对 / 数据依据 |
| 元数据 | 基础资料 |
| NAV / RFQ / Provider | 账户净值 / 询价 / 报价服务 |
| MarketData / TradingAPI / PrivateWS / AppWS | 行情数据 / 交易接口 / 账户连接 / 后台连接 |
| Funding / Delta | 资金费 / 未对冲金额 |

- 提示先说发生了什么、影响什么，再说可以做什么；请求编号、原始错误和协议字段放在技术详情。
- “已受理”不能改成“已成交”，“正在核对”不能改成“失败”，“已完成”不能改成“已盈利”。
- 缺失数据明确说明，不用零值或绿色状态补齐；旧数据可查看，但不能当作当前可执行条件。
- 不改内部字段、路由、状态枚举、幂等编号或 API 协议。自动化和手动操作使用同一套说法。
- 后台原始错误不能靠改文案掩盖；旧接口返回的文字仍要能识别，分类规则不能因为显示名称改变而失效。
- 文案改变后检查桌面与窄屏的换行、按钮和关键数字，避免长文字遮挡动作。
